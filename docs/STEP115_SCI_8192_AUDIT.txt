Scope and translated behavior
-----------------------------
Step 115 translates the software message core selected by the SCI IRQ front
near $C9F4 and the routines at $FA58..$FC71. The listing contains one top-level
device, ID $80, and mode descriptors for Modes 0 through 4.

Implemented behavior includes LFA58/LFA7A initialization, the shared ICB/OCB
status locations, device matching, biased length decoding, modulo-256 receive
checksum, input-buffer and Mode-2/3/4 mirror transfer, reply selection,
two's-complement transmit checksum, transmitter/wakeup register states, and
the source-specific Mode 0, 1, 2, 3 and 4 payload rules.

Executable arithmetic controls the translation where comments conflict or are
ambiguous. Mode 1 emits the mode plus 63 C75B table-selected bytes. Mode 2 uses
the descriptor NOUT=64 and therefore emits the mode plus 63 sequential bytes.
Modes 3 and 4 derive their output count from the received NIN value exactly as
LFBBB does. Mode 4 copies its ten control bytes to $0152..$015B and makes the
accepted lock/Mode-4 state visible to the scheduler-facing RAM flags.

Boundaries
----------
The PC HAL supplies complete received byte frames; electrical bit timing,
transceiver polarity, collision behavior and interrupt latency are not inferred.
RAM $0000..$04FF and the listing-proven EPROM ID bytes $C000/$C001 are readable.
An arbitrary Mode-2/3/4 ROM address that is not represented in the C calibration
model returns an explicit address/boundary result instead of invented data.
