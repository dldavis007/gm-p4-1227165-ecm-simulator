Result
------
Added docs/reference/TRANSMISSION_TCC_THEORY.md.

The chapter records the evidence-supported architecture as:

  F3 transmission/vehicle plant
      -> F2 firmware-visible selector/VSS stimuli
      -> F0 Segment-E TCC qualification/state
      -> F0 common raw output staging
      -> F4 external driver / brake-series-power / hydraulic clutch boundary

The chapter preserves these distinctions:
- selector/TCC state is firmware behavior; it is not by itself a complete
  physical transmission-switch model;
- VSS production is separate from the Segment-E TCC consumer;
- a firmware TCC request is distinct from raw ECM output and from actual clutch
  engagement;
- the external brake path can interrupt/release the physical TCC power path and
  must not be collapsed into a convenient firmware bit without evidence;
- transmission ratios, converter slip and vehicle dynamics in
  simulation/transmission_drive.inc.h are F3 test-plant assumptions, not PROM
  calibration or production-transmission facts;
- external driver polarity, hydraulic delay and clutch mechanics remain F4
  unless direct evidence closes them.

Code and regression impact
--------------------------
Documentation-only step. No C source, calibration, test, generated output or
frozen behavioral baseline changed.

Existing tests/tcc_transmission_regression.inc.h remains the regression proof
for the currently translated behavior. No new behavioral claim was introduced
that requires changing the baseline.

Unresolved boundaries retained
------------------------------
- exact external selector-switch electrical encoding where not directly proven;
- external TCC driver polarity where not closed by schematic evidence;
- exact brake-contact polarity/voltage throughout the physical series path;
- hydraulic apply/release delay and converter clutch capacity;
- real production gear ratios/slip curves inferred only from the PC plant;
- unexercised or variant-specific transmission behavior.

Conclusion
----------
Theory-of-operation Chapter 11 is now integrated at the same evidence-bounded
level as the preceding chapters. The repository can describe how the supplied
firmware qualifies and stages TCC control while keeping physical transmission
and clutch behavior outside the firmware-exact layer.
