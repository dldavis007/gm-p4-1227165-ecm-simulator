Findings
--------
1. MAP# and MAP2# have separate 18-kOhm/51-kOhm/0.47-uF conditioning paths to
   U10 A/D inputs AN3 and AN0 respectively.

2. CAL61 is mechanically mapped to 16055376 terminal 7, is common with J4 64
   in the reconstructed network, and meets the conditioned MAP net at U11 pin
   28. This proves a MAP-related U11 configuration boundary, not its function.

3. The supplied 9340 normal-operation listing has no explicit A/D request for
   channel 0/MAP2 or channel 3/MAP. Factory test scans channels 0-B, so the
   channels are observable there.

4. The principal firmware load at $0063 is produced at $D769-$D7A0 from
   MAF-derived airflow $00EA-$00EB multiplied by reference period $0095-$0096,
   then scaled by LC69A. It is not shown to be a direct MAP reading.

5. $0061 and $0062 are shifted load-history bytes in the executable sequence.
   The isolated source/ALDL label “Raw Ld Val” for $0061 is weaker than the
   instructions and is retained as a comment discrepancy.

6. Mixed “MAP Hi”/“MAF Hi” comments for $00B0 are resolved at the behavioral
   level: the code tests airflow, pump voltage, and Error-33/34 MAF thresholds.
   “MAF diagnostic counter” is the supported description.

Source and baseline impact
--------------------------
Documentation/evidence only. No C source, tests, generated outputs, or frozen
behavioral baselines changed.

Conclusion
----------
Step 132 closes the processor-visible load-production theory for this image
while leaving U11 MAP/CAL61 behavior and variant-dependent MAP use unresolved.
