BUA / GM 1227165 STEP-110 WHOLE-IMAGE COVERAGE AUDIT
====================================================

Purpose and evidence order
--------------------------
This audit compares the zero-error bua-hac.lst executable image with the
current C89 behavioral core. Emitted instructions, resolved targets, and RAM/
MPU address use outrank comments. `BUA` remains a source label and is not an
independently established calibration identity.

Coverage terms
--------------
  FULL-CORE   Internally executable behavior is scheduler-wired for this image.
  RAW-HAL     Exact source register values are produced; electrical behavior is HAL.
  PARTIAL     Useful source behavior exists, but at least one reachable route is absent.
  TEST-ONLY   Translated helper/regression exists but is not in the live call graph.
  BOUNDARY    Required code or physical behavior is outside the supplied PROM.
  UNPORTED    Listing-backed executable behavior has no equivalent in the live core.

Step-110 Segment-1 closure
---------------------------
Before Step 110, Segment 1 computed a software-side summary but did not write
the source MPU and parallel-I/O addresses. Step 110 now preserves:

- the two-pass >=171 battery latch and forced-all-off continuation;
- engine-off ordinary $D000 and field-diagnostic $DFFF staging;
- normal AIR, acceleration-enrichment, TCC, purge, fan, and EGR selection;
- Mode-4 raw PWM overrides from L0152/L0153/L0156/L0157;
- LC014=$B4, LC015=$04, and LC017=$00 branch consequences;
- direct writes to $3FCC, $3FD2, $3FD4, $3FD6, $3FD8, and $4004;
- complement-before-scaling for normal purge/EGR, but not Mode-4 forcing;
- 16-bit wrap in the source's $34xx shift-by-two PWM construction.

The LF3B5 delays between engine-off MPU writes do not alter source RAM. They
remain target-HAL timing rather than an invented PC delay. Physical polarity,
driver circuitry, and actuator response also remain HAL responsibilities.

Normal-driving conclusion
-------------------------
All 16 major-table entries now have their internally defined normal software
behavior represented, with entries 0 and 8 proven no-ops and entry 4 explicitly
external. The ordinary odd/even fuel, spark, injector, IAC, and major scheduler
paths are connected. This is strong behavioral coverage, but it is not yet a
claim of whole-ROM equivalence because startup, key-off, SCI service, test
modes, vectors, and external hardware still differ as ranked above.

Next implementation
-------------------

test-only role, reconcile them again against $D387..$D3D2 and $D6D1..$D727,
and connect the key-off path to the odd scheduler. The SWI powerdown endpoint
must remain an explicit HAL/event boundary rather than being executed on PC.
