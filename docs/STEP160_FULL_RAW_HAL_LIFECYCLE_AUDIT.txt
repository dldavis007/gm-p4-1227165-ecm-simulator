IAC integration defect found and corrected
------------------------------------------
The first complete-cycle run exposed a real disagreement between two translated
paths. The shutdown producer issued decimal 144 when reopening the IAC from the
hard stop. The common motor consumer uses command bit 7 as its direction carry,
so $90 was interpreted as a closing command and the motor remained at zero.

The assembled source at $D3AC-$D3B4 does not simply calculate an unbounded
park-minus-position value. It performs:

  SUBA LC62F
  NEGA
  BPL LD3B4
  LDAA #127

With position zero and LC62F=144, the 8-bit result after NEGA is $90. Its sign
bit is set, so the source replaces it with 127 before storing L0101. Later even
passes recompute the remaining distance until it fits the positive command
range. The corrected translation now preserves those intermediate 8-bit values
and the source sign test.

This is an F0 behavioral correction supported directly by executable bytes. It
does not change motor electrical assumptions or command encoding.
