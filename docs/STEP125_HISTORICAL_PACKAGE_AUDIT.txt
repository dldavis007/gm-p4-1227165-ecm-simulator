BUA / GM 1227165 STEP-125 HISTORICAL PACKAGE AUDIT
==================================================

Purpose and limits
------------------
This documentation-only step completes the first historical-package manifest
required by Step 123. It audits seven unique ZIP packages, proves the duplicate
Step-111 copy byte-identical, changes no behavioral C code, and deletes nothing
from the historical collection. The packages are not committed because their
useful audit, output, warning, and signature evidence is already represented in
the repository and exact historical distribution reconstruction is not a
project requirement.

Content comparison
------------------
All eight packages were expanded for inspection, producing 399 files including
the duplicate Step-111 tree. Package-relative paths and SHA-256 values were
compared with the current repository and with the Step-105 and Step-111 Git
checkpoints.

The named Step-104 through Step-111 audit documents, regression outputs, and
Step-104 signature record inside the packages match their committed records.
The Step-105 and Step-111 modular source trees also match their corresponding
Git checkpoints except for checkout line-ending normalization in the two
Windows batch files. Later main-branch source files correctly differ because
Steps 112 through 121 extended the active implementation.

The Step-109 and Step-110 packages contain intermediate source/build states not
represented as separate commits in the current Git history. The Step-104
OnlineGDB and split packages likewise retain distribution-specific monolithic
and split layouts. Those packaging states are redundant for continued
development and are deliberately excluded rather than copied into Git. Their
filenames, sizes, file counts, and hashes above retain an exact identity record.

Authority and historical statements
-----------------------------------
These packages are historical checkpoints, not current instructions. The old
Step-104 baseline statement naming bua-hac.txt as authoritative is superseded.
Only evidence/firmware/bua-hac.lst may be used as firmware evidence.

Cleanup classification
----------------------
The seven unique source packages are deliberately excluded as redundant
historical distributions. The exact manifest hashes above allow later copies to
be recognized. They are cleanup candidates, subject to the user's later
retention decision. The numbered Step-111 copy is a proved duplicate candidate.
This audit does not authorize or perform deletion.

Other historical packages remain outside this completed manifest and are not
cleanup candidates on the strength of Step 125. The Step-104 glossary and
hardware-clarification Markdown review, original PROM/S-record comparison
search, external-PDF rights decision, and DG128 target-port classification also
remain open.
